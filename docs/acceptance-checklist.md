## 1. 前置

两个终端（细节见 [`platform-plan.md`](platform-plan.md) §8.1）：

```shell
# 终端一: 后端
cd backend && python -m app.main          # 127.0.0.1:8000

# 终端二: 前端
cd frontend && npm run dev                # http://localhost:5173/
```

- 浏览器开 `http://localhost:5173/`。**不要用 `http://127.0.0.1:5173`** —— Vite 只绑了 `[::1]`，
  那个地址连不上，容易被误判成「服务没起来」。`/api` 由 Vite 的 `server.proxy` 转到后端。
- 需要两个账号：甲（普通用户）、乙（管理员）。账号只能在 `/users` 里由管理员建（登录页没有注册入口），
  首次启动的空库必须给出初始管理员口令，否则后端启动即抛错。
- 引擎与行情数据要在位（`../QuantTrading/bin/Release`、仓内的 `market-data/Bar`），
  外加上游的行情组件 `../QuoteHub`（平台查它的库判"本地行情够不够"，不够就调它的 CLI 下载）。
  三样缺任何一样，第 4 节提交都会失败——判"够不够"这件事本身就要查组件库。
- 不想碰 `backend/data/` 与 `runs/`：把 `QUANT_DATABASE_URL`、`QUANT_RUNS_ROOT`、
  `QUANT_USER_LIBRARY_ROOT` 指到临时目录，就能用一次性库走完整套。
- **判「未登录态」要清 `localStorage` 的 `quantplatform.access-token`**，或直接用无痕窗口。
- 改了 `index.html` 或 `public/` 之后要看标签页图标，**必须重启 dev server 或 `Ctrl+F5`**，普通刷新
  拿不到。

## 11. P6 多轮对比与配置模板

前置同第 1 节。先凑出**两轮同参数、只有 `GridStep` 不同**的回测：在 `/runs/new` 选同一个策略与
版本，`GridStep` 填 `0.01` 提交、等它 `succeeded`；再选同一个策略、把 `GridStep` 改成 `0.02` 提交，
其余字段（标的 / 日期 / 初始资金 / 别的参数）逐字不动。

- [ ] 各轮的详情页右侧有「加入对比」；点它落在 `/compare?ids=<这一轮>`，选择器里**只勾上这一轮**
      （它不合并"上一页勾了什么"——那边是另一个页面，唯一状态源在它自己的地址栏上）。
- [ ] 再勾上另一轮 → 地址栏成两个 id，表格长出第二列，列头是「第 1 轮」「第 2 轮」。
- [ ] 页面自上而下三张卡：**选择要对比的运行 → 权益曲线叠加 → 指标并列**。图上两条线，
      图例按轮次。
- [ ] 「提交的参数」一节里 `GridStep` 两列分别是 `0.01` 与 `0.02`，**数值不带千位分隔**
      （参数值要与 `BackTest.json` 逐字对得上）；上面几节的指标两列互不相同。
- [ ] **两条曲线各自的拐点与它们详情页上的单轮曲线一致**（同一天同一个权益值）；两轮区间相同时
      线是重合度很高的两条，别把"看起来像一条"当成 bug。
- [ ] 选满 6 轮后，剩下没勾的勾选框**置灰**并出现上限提示。
- [ ] 把地址栏的 `ids` 换成一个**不属于你**的运行号 → **整页报错**且**表格不出现**，选择器还在

- [ ] 手动删掉某一轮的 `runs/<RunId>/BackTest_<RunId>.db` → 刷新对比页：**只有那一列**的表头位置

## 12. P6 配置模板与 P7 删除 / 保留

- [ ] `/runs/new` 选策略 → 填好表单 → 「存为模板」→ 输名字 → 保存 → 提示成功，选择器里多一份。
- [ ] 换一个策略再换回来（或刷新页面）：选中那份模板 → 「套用」→ **运行级字段与策略参数都回来了**，
      提示条写明套的是哪一份模板（与"上次提交的参数"那句文案不同）。
- [ ] 模板名重名 → 「同名模板已存在」；名字留空 → 「模板名不能为空白」；**表单本身填错时点「存为模板」
      → 先看见表单自己的那批错误，弹窗不打开**（存一个提交不出去的模板是陷阱）。
- [ ] 「删除运行」只在**终态**轮的详情页出现，且与「取消运行」互斥；运行中的轮上只有「取消运行」。
- [ ] 删一个 `succeeded` 的轮：确认 → 成功提示 → **跳回 `/runs` 且列表少一行**，跳转后不再有请求
      打到已删的轮（不该看见 404 的闪烁）。到 `runs/<RunId>/` 看：**整个目录不见了**。
- [ ] 浏览器**后退**回那个已删的详情页 → 「运行不存在」，不白屏。
- [ ] 直接对未结束的轮发 `DELETE`（curl 或 `/docs`）→ **409**，且库里那一行还在。
- [ ] **保留策略默认关**：不动任何配置连跑 3 轮 → `/runs` 里**一轮不少**，`runs/` 下一个目录没少。
- [ ] 关掉后端，设 `QUANT_RUN_RETENTION_ENABLED=true`、`QUANT_RETAINED_RUNS_PER_USER=2`，用**同一个**
      `QUANT_RUNS_ROOT` 起回来 → 启动那一刻每用户只剩最新 2 轮，旧轮在 `runs/` 下的目录也一起没了，
      **最新那一轮在**。
- [ ] 开着 N=2 再跑一轮 → 它一落终态，**最旧的那一轮随即消失**；此时**它自己的详情页仍然正常**
      （刚结束的这一轮不参与本次清扫）。
- [ ] 设回 `QUANT_RUN_RETENTION_ENABLED=false` 再跑一轮 → 旧轮不再被删。
- [ ] 设一个非法值（如 `QUANT_RUN_RETENTION_ENABLED=enable`）起后端 → **启动即报错**，
      不是安静地什么都不删（那与"这项没生效"无法区分）。

> **注意**：`QUANT_RETAINED_RUNS_PER_USER=0` 会在构造配置时直接抛错——想"一轮不留"就关掉
> `QUANT_RUN_RETENTION_ENABLED`，而不是把 N 设成 0。

> **注意**：目录**删不掉**时接口回 409 且**保留行**（最常见的原因是孤儿进程还占着结果库，
> Windows 上报 `WinError 32`；见 [`platform-plan.md`](platform-plan.md) §12.12）。这是正确行为，
> 不是缺陷——结束那个进程后重试即可。
