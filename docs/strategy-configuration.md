# 策略配置模板

上传策略时要一并提供的那份 `.json` —— **策略启动时真正去读的那一份**。它同时是提交页的参数模板：

- **键即参数**：每个键渲染成一个控件，**键集由这份文件固定**，提交页只能改值。
- **值即默认值**：表单初值就是文件里的取值。
- **平台拿它当底稿**：提交时在它之上叠用户的编辑，再**覆写**三个运行级键；其余键（包括平台认不得的
  数组、对象、`null`）原样保留。

平台不读策略自带的配置文件来"对照"，也不认识任何参数声明：没有标题、没有范围、没有可选项、没有分组。
**参数合不合法由策略自己守**，平台只保证"你上传的那份配置，跑起来就是这份配置改了几格"。

## 三个平台键

三个运行级取值由平台**覆写**进策略配置，键名固定，与引擎自带的 `Configs/TestStrategyGrid.json`
同拼写：

| 键 | 取值来自 | 说明 |
| ---- | ---- | ---- |
| `ExchangeId` | 提交页的合约 | `SSE` / `SZSE` |
| `InstrumentId` | 提交页的合约 | 6 位代码 |
| `BarPreces` | 提交页的周期 | 策略的**订阅周期**，见下 |

模板里没有这三个键就新增，有就覆写。它们**不出现在参数区**：参数区再给一次只会让用户以为改得动。
`BarPreces` 这个拼写是引擎侧的既有写法，不是笔误。

**注意**：策略里若本来就有个叫 `ExchangeId` 的参数，它会被平台覆写掉。给参数起名时避开这三个键。

## 两种周期不是一件事

- **落盘精度**：磁盘上的行情只有 5m 一档，引擎那份 `BackTest.json.BarPreces` 恒为 `5m`，由平台
  写死，用户改不动。
- **订阅周期**：提交页选的 `5m` / `15m` / `30m` / `60m` 写进**策略配置**的 `BarPreces`，是策略声明
  的聚合目标。选 15m 时，引擎在运行时把 5m 聚合成 15m。

选一个引擎聚合不出来的周期（比如 `1d`）**不是静默零成交**：引擎在装载期就判
`ErrorMarketDataNotExist` 拒掉整轮，报错收场。但那一轮已经白跑了，所以提交页只给清单内的值。

## 上传

multipart 两个文件字段：`source`（`.py`）与 `configuration`（`.json`）。

- 两个文件名都必须是**裸文件名**且各带自己的后缀（`source` 须以 `.py` 结尾、`configuration` 须以
  `.json` 结尾）。不得带路径分隔符，不得含 `<` `>` `:` `"` `|` `?` `*` 与控制字符，不得有首尾空白，
  不得是 `.` / `..`，不得是 `con` / `nul` / `com1` 一类 Windows 保留设备名，也不得与引擎自己要读写
  的 `BackTest.json` / `Sessions.json` / `result.json` 重名。两个名字都不得超过 128 个字符。
- 送完整路径**直接拒**，不替你取末段：文件名是策略源码里 `open()` 的那个名字，平台替它认领一个
  用户没打算用的名字，症状是「跑起来了但读不到配置」。
- 配置须是 **UTF-8 文本**，**顶层是 JSON 对象**（数组与标量拒），不超过 64 KiB，键不超过 200 个、
  每个键名不超过 64 字符且非空。
- 配置里不得出现 `NaN` / `Infinity` / `-Infinity` 这几个非 JSON 字面量。
- 判重的键是 `(源码内容, 配置原文)`：同一份源码配不同配置，本就是**一份新版本**。

平台按**版本**存这两份文件：`.py` 改了就连配置一起传新版本，旧版本不受影响。

## 可以直接用的示例

[`strategy-configuration.example.json`](strategy-configuration.example.json) 配引擎仓
`QuantTrading/bin/Release/grid_strategy.py` 使用。这一对正是真引擎验收
（`backend/tests/test_real_engine_acceptance.py`）跑过的那一对。

它**刻意不写**三个平台键：那三行由平台覆写，写在模板里只会被盖掉。想先走通一条完整链路，
拿这两份文件即可。

## 参数区里看不到的键

两类键不出现在参数区，但都会**原样写进**策略配置：

- **三个平台键**：各有自己的控件，见上。
- **取值是数组 / 对象 / `null` 的键**：JSON 里没有"空的数值输入框"，这类取值也没有自然的控件形态，
  硬造一个只会引入"存得进去、读不出来"的一类失败。提交页会把它们**列出来但改不了**，
  取值恒为模板里的那个。

另有几类键**上传时就拒**，压根进不来：键数超过 200、键名为空或超过 64 字符、顶层不是对象、
配置超过 64 KiB，见上「上传」。

## 把自己已有的策略接进来

拿策略**实际读到的那个配置文件**直接上传即可，不需要改写：

- 由提交页填、每个策略都一样的（交易所 / 标的 / 周期）**留在文件里就行**——平台会覆写它们。想少一分
  歧义，也可以先把这三行删掉，平台会按固定键名补上。
- 策略自己的可调项什么都不用做，逐个键长成一个控件。
- 键名一律照抄里的大小写（`ExchangeId`、`BarPreces` 这种），程序员的直觉在这里不管用。

**参数值类型写错是新的静默风险**：把 `GridStep` 的值写成字符串 `"0.01"`，表单上就是个文本框，
提交上去策略拿到的是字符串。类型以文件里的取值为准，写的时候留意。

## 配置放哪里

- **演示件**是 `docs/strategy-configuration.example.json`，与本文档同目录：它是文档的一部分，只读，
  不针对某一个策略。里面那个账号是占位值，跑之前换成自己的。
- **每个策略自己的配置与它的 `.py` 放在一起**（策略源码所在目录），因为策略启动时读的就是它。
