# 策略 manifest

上传策略时要提供的那个 JSON。它声明平台运行该策略所需的全部信息：入口文件名、策略配置文件名、支持的
行情模式、运行级字段写进策略配置时的键名，以及策略自己的参数。

**平台按 manifest 渲染策略配置，不读策略自带的配置文件** —— 版本目录里只有源码与 manifest，没有配置
文件可作底稿。这条是理解下面每个字段的前提。

提供方式两种，落到同一个请求字段：在上传表单里直接粘贴文本，或点「读入 manifest.json」选一个文件。
上限 64 KiB。

## 可以直接用的示例

[`strategy-manifest.example.json`](strategy-manifest.example.json) 是一份完整、已校验的 manifest，
配引擎仓 `QuantTrading/bin/Release/grid_strategy.py` 使用。这一对正是真引擎验收
（`backend/tests/test_real_engine_acceptance.py`）跑过的那一对：三个月的 5m 回测、84 笔成交、
2928 根 bar。想先走通一条完整链路，拿这两份文件即可。

它与那份策略自带的 `Configs/TestStrategyGrid.json` 是**逐键对应**的：平台渲染出来的配置，键名与取值
与那份文件完全一致（只有次序不同，JSON 对象无序，无影响）。

## 顶层字段

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `entry_filename` | 是 | 入口文件名，须以 `.py` 结尾 |
| `config_filename` | 是 | 策略配置文件名，须以 `.json` 结尾 |
| `supported_match_modes` | 是 | 非空数组，取值 `Bar` / `Tick`，不得重复 |
| `run_field_keys` | 否 | 运行级字段 → 策略配置键名 |
| `params` | 否 | 策略自己的参数 |

两个文件名都必须是**裸文件名**：不得带路径分隔符，不得含 `<` `>` `:` `"` `|` `?` `*` 与控制字符，
不得有首尾空白，不得是 `con` / `nul` / `com1` 一类 Windows 保留设备名，也不得与引擎自己要读写的
`BackTest.json` / `Sessions.json` / `result.json` 重名。校验器逐条拦，报错只说字段名与原因。

`supported_match_modes` 的取值是引擎字面量，大小写不可改。写 `Tick` 能上传成功，但**提交侧一律拒绝
Tick**，所以当前只有 `Bar` 是真的能跑起来的。

`run_field_keys` 的三个字段都可省略，**省略即该字段不写进策略配置**：

| 键 | 来源 | 说明 |
| ---- | ---- | ---- |
| `exchange_id` | 提交页的交易所 | 引擎不认识，只有策略用 |
| `instrument_id` | 提交页的标的 | 同上 |
| `bar_period` | 提交页的 K 线周期 | **建议一定映射**，见下 |

## `params`

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `key` | 是 | 写进策略配置的键名，只含字母数字与 `.` `_` `-`，≤ 64 字符 |
| `label` | 否 | 表单上的标题，空则回落成 `key` |
| `type` | 否 | `integer` / `number` / `string` / `boolean`，缺省 `string` |
| `default` | 否 | **省略即必填** —— 表单上不填就提交不了 |
| `minimum` `maximum` | 否 | 只对 `integer` / `number` 开放 |
| `options` | 否 | 可选取值，形如 `[{"value": 1, "label": "一档"}]` |
| `group` | 否 | 表单分组标题，空串即不分组 |

没有 `required` 标志：`required: true` 配 `default: 10` 是自相矛盾的组合，而「没有 `default` 就必须
由提交方给出」已经完整表达了同一件事。同一组的参数按声明次序排在一起，故**次序就是作者意图**。

`options` 一给出，表单就渲染成下拉框（取值按类型保留，`1` 与 `"1"` 不是同一个取值）；`type: boolean`
渲染成复选框。默认值走的是与提交值**同一套**校验，写一个自己不合法（越界、不在 `options` 里、类型
不符）的默认值会在**上传时**就被拒，而不是等到提交。

## 两条最容易踩的坑

**一、漏声明 = 该键整个消失。** 平台渲染出的策略配置**恰好**是「已映射的运行级字段 ∪ 已声明的参数」，
没有第三类键。策略里 `config["X"]` 直接取用的话，漏声明 `X` 不是"保持原样"，而是以未捕获异常
（退出码 1）收场。另外 `config_filename` 必须与策略里打开的那个名字**一字不差**——作业目录里的路径
相对 CWD 解析，而这个文件由平台按这个名字生成，策略源码里那份同名文件**不会**被带上去。

**二、`bar_period` 不映射会静默 0 成交。** K 线周期要写两处：引擎配置里的 `BarPreces` 是引擎实际
聚合周期，策略配置里那个（键名由 `run_field_keys.bar_period` 给出）是策略的期望周期。**两者不一致
时策略收不到 bar、一笔都不成交，而且不报错。** 有映射时两处由平台写同一个值，一致性是结构性的；
不映射则平台只写引擎那一份，这份差异由策略作者承担。

## 把自己已有的策略接进来

拿策略**实际读到的那个配置文件**倒推最快：文件里每个键，要么是一个参数，要么是一个运行级字段。

- 由提交页填、每个策略都一样的（交易所 / 标的 / K 线周期）→ 进 `run_field_keys`。
- 策略自己的可调项 → 进 `params`，`type` 按文件里的取值定，`default` 取原来那个值。

键名一律**照抄配置文件里的大小写**（`ExchangeId`、`BarPreces` 这种，程序员的直觉在这里不管用）。
最后并起来数一遍：两组键的并集应当**恰好**是那把键，不多不少——多了策略用不到，少了就是坑一。

## manifest 放哪里

- **演示件**是 `docs/strategy-manifest.example.json`，与本文档同目录：它是文档的一部分，只读，不针对
  某一个策略。
- **每个策略自己的 manifest 与它的 `.py` 放在一起**（策略源码所在目录），因为它描述的就是那份源码，
  两者要一起改、一起走。平台按**版本**存 manifest：`.py` 改了就连 manifest 一起上传新版本，旧版本
  的 manifest 不受影响。
- 想在上传页做一个「下载示例」的链接，把演示件挪到 `frontend/public/` 即可（Vite 按 URL 直接提供），
  代价是它会进前端产物；目前选择放在文档里。
